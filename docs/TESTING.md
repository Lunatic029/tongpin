覆盖的核心逻辑：

1. 仅启用成员参与发言；@成员优先；多人场景避免同一人连续发言。
2. 不同角色的性格进入各自提示词；最近群聊进入上下文；演示消息和系统事件排除。
3. 上下文长度受控并保留最近内容；请求中不包含头像。
4. 备份往返保持角色与消息；非法格式、过大文件、重复成员 ID 被拒绝。
5. 不可信备份中的模型、回复数量、头像来源等受到约束；额外密钥字段不导入。
6. v1 单群数据及备份迁移为 v2，保留消息、角色和休息状态。
7. 同一角色跨群复用，多个群的消息与 API 上下文互相隔离。
8. 角色编辑同步到所有加入的群，休息状态仅影响指定群。
9. 从本群移出保留角色库和其他群的成员关系，可重新添加且不重复。
10. 删除群聊保留角色库与其他群，至少保留一个群。
11. 彻底删除角色时清理所有群的成员与休息引用，保留历史消息。
12. 多群备份保留选中群、记录、成员关系和独立休息状态。
13. 无效成员引用、重复群 ID、缺失群列表及非法休息成员被拒绝。
14. 群容量和角色引用错误不会部分修改原数据。
15. 同名角色/群被拒绝；允许创建空群后再邀请角色。

应用控制逻辑覆盖：

1. API 请求尚未完成时切群，取消请求并忽略迟到的回调。
2. 两条回复之间切群，旧群不会继续发起下一次请求。
3. 从界面动作创建群、复用角色，以及各群输入草稿独立。
4. 从本群移出和从角色库删除的影响范围正确。
5. 导入多群备份会取消此前生成，旧回调不会写入恢复后的群。

## 复现核心测试

安装 Node.js 20 或以上，在项目根目录执行：

```sh
node tests/core.test.cjs
node tests/controller.test.cjs
```

## 运行浏览器交互测试

安装 Python、Playwright 和 Chromium。脚本优先使用 `CHROMIUM_PATH` 环境变量指定的浏览器，其次使用 PATH 中的 Chromium，否则使用 Playwright 自带浏览器。

```sh
python -m pip install playwright
python -m playwright install chromium
python tests/ui_test.py
```

脚本包含手机尺寸布局、多群创建和切换、共享角色编辑、按群休息、成员增删改、本地持久化、演示回复、停止回复、HTML 文本安全显示、备份恢复，以及通过模拟原生接口验证的发言顺序、上下文串联、错误重试。模拟接口测试不能替代真实 DeepSeek 接口验证。

## 安卓验收步骤

1. 构建 debug APK，安装到 Android 8+ 设备，更新 System WebView。
2. 首次打开确认页面显示，测试键盘弹出、旋转屏幕、系统返回键和底部导航。
3. 添加角色，修改名字、性格、头像、活跃度，重启应用确认保存。
4. 将成员设为休息，确认不会自动发言；移出成员，确认旧消息仍保留。
5. 开启演示模式，发送消息，确认出现演示标识；回复过程中点击停止，确认后续结果不再追加。
6. 保存有效 API Key，测试连接；关闭演示模式发送消息，确认请求成功、角色语气不同、后续成员能接前一位的话。
7. 测试无效 Key、余额不足、断网和超时；确认错误提示且重试不重复追加用户消息。
8. 请求期间切到后台，返回后确认已停止；再发消息确认可正常恢复。
9. 导出 JSON，检查不包含 Key，清空记录后导入恢复；测试无效 JSON 不覆盖当前数据。
10. 重启设备确认密钥仍可用；删除密钥确认真实回复被拦截。

2. 创建“电影群”和“游戏群”，两群都加入同一位角色，分别聊天，确认记录与背景互不混用。

4. 从电影群移出共享角色，确认角色库与游戏群保留，可再次加入。

6. 删除电影群，确认游戏群和角色库仍保留。
7. 导出多群备份，重新导入，确认当前群、群背景、共享成员关系、休息状态及各群历史均恢复。
